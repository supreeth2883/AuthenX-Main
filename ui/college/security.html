Double-Signing Model
How AuthenX ensures credentials are authentic and current
① Issuance Signature

Generated once when the credential is issued. Signed by the college's Ed25519 key in HSM over the canonical JSON hash.

② Live Verification Signature

Generated fresh at every employer check. Connector re-fetches live ERP data, rebuilds canonical JSON, re-signs with a unique nonce.

Replay resistance: Each live verification uses a unique nonce. Even if an interceptor captured a verification response, replaying it would fail because the nonce would not match the server's expectation. Both signatures must match for a credential to be VERIFIED.
