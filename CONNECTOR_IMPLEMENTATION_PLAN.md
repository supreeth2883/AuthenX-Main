# AuthenX Connector — Implementation Plan
## MySQL Adapter (v1) · Node 22 · Zero External Dependencies

---

## What the Connector Does

The connector is a small Node.js HTTP service that runs **inside the college's network**.

When AuthenX needs to live-verify a student, it sends a signed request to the connector. The connector:
1. Receives `{ student_ref_token, nonce, request_signature }`
2. Queries the college's MySQL database (read-only, single record)
3. Maps DB fields to AuthenX's standard output format
4. Signs the response with the college's Ed25519 private key
5. Returns `{ name, degree, branch, cgpa, graduation_year, status, live_signature }`

AuthenX receives only the signed response — never touches the DB directly.

## Step 2 — Field Mapping Config (config.json)

Each college has a different DB schema. The config maps their columns to AuthenX's standard fields.

```json
{
  "college_id": "iitb",
  "college_name": "IIT Bombay",
  "db": {
    "table": "students",
    "ref_column": "enrollment_number"
  },
  "field_mapping": {
    "name":            { "type": "concat", "columns": ["first_name", "last_name"], "separator": " " },
    "degree":          { "type": "column", "column": "program_name" },
    "branch":          { "type": "column", "column": "department" },
    "cgpa":            { "type": "column", "column": "final_cgpa" },
    "graduation_year": { "type": "year_from_date", "column": "graduation_date" },
    "issue_date":      { "type": "column", "column": "convocation_date" },
    "status":          {
      "type": "map_values",
      "column": "enrollment_status",
      "active_values": ["ACTIVE", "GRADUATED", "ALUMNI"],
      "inactive_values": ["WITHDRAWN", "EXPELLED", "SUSPENDED"]
    }
  }
}
```

**Supported field types:**
- `column` — direct column value
- `concat` — join multiple columns with a separator
- `year_from_date` — extract year from a date column
- `map_values` — map string values to active/inactive boolean

## Step 3 — Core connector.js Implementation

```javascript
// connector.js
// AuthenX College Connector — MySQL Adapter
// Node 22 built-in modules ONLY — zero npm dependencies

import { createServer } from 'node:http';
import { createConnection } from 'node:net'; // for MySQL protocol
import { readFileSync } from 'node:fs';
import { createPrivateKey, sign, createPublicKey, verify } from 'node:crypto';
import { createHmac } from 'node:crypto';

// ─── Load config ───
const config = JSON.parse(readFileSync('./config.json', 'utf8'));
const env = parseEnv('.env');

// ─── Ed25519 key setup ───
// Build PKCS8 DER from raw 32-byte seed
function buildPrivateKeyFromHex(hexSeed) {
  const PKCS8_PREFIX = Buffer.from('302e020100300506032b657004220420', 'hex');
  const seedBuf = Buffer.from(hexSeed, 'hex');
  const pkcs8Der = Buffer.concat([PKCS8_PREFIX, seedBuf]);
  return createPrivateKey({ key: pkcs8Der, format: 'der', type: 'pkcs8' });
}

const privateKey = buildPrivateKeyFromHex(env.CONNECTOR_PRIVATE_KEY_HEX);
```

> **Implementation Note for Next Session:**
> The MySQL wire protocol is complex. Two valid approaches:
>
> **Approach A (Recommended for demo):** Bundle a single-file mysql2 equivalent using only Node built-ins. This requires implementing:
>   - TCP connection to MySQL
>   - Initial handshake packet parsing
>   - mysql_native_password authentication (SHA1-based)
>   - COM_QUERY packet sending
>   - Text resultset packet parsing
>
> **Approach B (Fastest for demo):** Use a shell subprocess to run `mysql -u user -p... -e "SELECT..."` and parse JSON output. Zero protocol code needed.
>   ```javascript
>   import { execSync } from 'node:child_process';
>   const result = execSync(
>     `mysql -h${host} -u${user} -p${pass} ${db} --json -e "${sql}"`
>   );
>   ```
>
> **Approach C (Production):** Use the `mysql2` npm package. For demo this is fine since it only runs on the college's machine, not the AuthenX cloud server.

## Step 5 — Field Mapping Engine

```javascript
function applyFieldMapping(row, mapping) {
  const result = {};

  for (const [outputField, spec] of Object.entries(mapping.field_mapping)) {
    switch (spec.type) {

      case 'column':
        result[outputField] = row[spec.column] ?? null;
        break;

      case 'concat':
        result[outputField] = spec.columns
          .map(col => row[col] ?? '')
          .filter(Boolean)
          .join(spec.separator || ' ');
        break;

      case 'year_from_date':
        const d = row[spec.column];
        result[outputField] = d ? new Date(d).getFullYear() : null;
        break;

      case 'map_values':
        const val = row[spec.column];
        result[outputField] = spec.active_values.includes(val)
          ? 'active'
          : spec.inactive_values.includes(val)
          ? 'inactive'
          : 'unknown';
        break;
    }
  }

  return result;
}
```

## Step 6 — Request Handler (HTTP Server)

```javascript
const server = createServer(async (req, res) => {

  // ── IP whitelist check ──
  const clientIP = req.socket.remoteAddress;
  const allowed = env.ALLOWED_IPS.split(',');
  if (!allowed.includes(clientIP)) {
    res.writeHead(403); res.end('Forbidden');
    return;
  }

  // ── Only POST /verify ──
  if (req.method !== 'POST' || req.url !== '/verify') {
    res.writeHead(404); res.end('Not found');
    return;
  }

  // ── Parse body ──
  const body = await readBody(req);
  let payload;
  try { payload = JSON.parse(body); } catch {
    res.writeHead(400); res.end('Bad JSON');
    return;
  }

  const { student_ref_token, nonce, request_signature } = payload;

  // ── Validate required fields ──
  if (!student_ref_token || !nonce) {
    res.writeHead(400); res.end(JSON.stringify({ error: 'Missing fields' }));
    return;
  }

  // ── Validate nonce freshness (within 30 seconds) ──
  // In production: maintain nonce registry to prevent replay attacks
  // For demo: validate timestamp embedded in nonce

  // ── Query DB ──
  const refColumn = config.db.ref_column;
  const table = config.db.table;
  const sql = `SELECT * FROM \`${table}\` WHERE \`${refColumn}\` = ? LIMIT 1`;

  let row;
  try {
    const rows = await mysqlQuery(dbConfig, sql, [student_ref_token]);
    if (!rows.length) {
      res.writeHead(404);
      res.end(JSON.stringify({ error: 'Student not found', ref: student_ref_token }));
      return;
    }
    row = rows[0];
  } catch (err) {
    console.error('[connector] DB error:', err.message);
    res.writeHead(500);
    res.end(JSON.stringify({ error: 'Database error' }));
    return;
  }

  // ── Apply field mapping ──
  const mapped = applyFieldMapping(row, config);

  // ── Build canonical message for signing ──
  // Same deterministic JSON format as AuthenX crypto module
  const canonical = buildCanonicalForSigning(mapped, nonce, config.college_id);

  // ── Sign with Ed25519 ──
  const sig = sign(null, Buffer.from(canonical), privateKey);
  const live_signature = sig.toString('base64');

  // ── Respond ──
  const response = {
    college_id: config.college_id,
    student_ref_token,
    nonce,
    ...mapped,
    live_signature,
    signed_at: new Date().toISOString()
  };

  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify(response));
});
```

## Step 7 — Canonical Signing Format

The connector must produce the same canonical JSON that AuthenX's crypto module expects, so the hash comparison passes.

```javascript
function buildCanonicalForSigning(fields, nonce, college_id) {
  // EXACT same field order as src/crypto/index.js buildCanonicalJson()
  return JSON.stringify({
    student_ref_token: fields.student_ref_token || '',
    college_id:        college_id,
    name:              fields.name || '',
    degree:            fields.degree || '',
    branch:            fields.branch || '',
    cgpa:              String(fields.cgpa || ''),
    graduation_year:   String(fields.graduation_year || ''),
    issue_date:        fields.issue_date || '',
    status:            fields.status || '',
    nonce:             nonce
  });
}
```

> **Critical:** This field order must exactly match `buildCanonicalJson()` in `src/crypto/index.js`.
> If the order differs, the hash won't match and verification will fail.

## Step 8 — Security Hardening Checklist

For each deployed connector, verify:

- [ ] **Read-only DB user** — `GRANT SELECT ON student_records.* TO 'authenx_readonly'@'localhost'`
- [ ] **IP whitelisting** — Only AuthenX server IPs can reach port 9000
- [ ] **HTTPS in production** — Use nginx reverse proxy with SSL cert
- [ ] **Nonce replay prevention** — Track used nonces in memory (TTL: 60s)
- [ ] **Request rate limiting** — Max 10 requests/second per IP
- [ ] **Private key isolation** — Key stored in .env, not in config.json
- [ ] **Firewall rule** — Block all inbound except port 9000 from AuthenX IPs
- [ ] **Logging** — Log all verification requests (ref_token + timestamp only, no PII)

```

  ↓
  1. College provides DB schema (table/column names)
  2. AuthenX creates config.json mapping
  3. AuthenX generates college Ed25519 keypair:
     generateEd25519KeyPair() → { privateKeyHex, publicKeyHex }
  4. Register publicKeyHex in AuthenX DB (colleges table)
  5. Share privateKeyHex securely with college IT

Day 2: College IT installs connector
  ↓
  6. College IT: git clone authenx-connector
  7. Edit .env (DB creds + CONNECTOR_PRIVATE_KEY_HEX from step 5)
  8. Copy config.json from AuthenX
  9. Create MySQL read-only user:
     CREATE USER 'authenx_readonly'@'localhost' IDENTIFIED BY 'password';
     GRANT SELECT ON student_records.* TO 'authenx_readonly'@'localhost';
  10. node connector.js → starts on port 9000

Day 2 (afternoon): AuthenX validates
  ↓
  11. AuthenX sends test request with a known student ref token
  12. Connector responds with signed data
  13. AuthenX verifies signature using college's public key
  14. ✓ College is live on AuthenX
```
